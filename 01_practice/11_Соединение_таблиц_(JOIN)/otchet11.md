## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Запрос с ошибкой:** 
  ```sql
  SELECT p.title, c.name FROM product p JOIN categories c;
  ```
* **Объяснение ошибки:** В данном запросе полностью пропущено ключевое слово `ON` (или `USING`) с указанием конкретного условия связывания таблиц по первичному и внешнему ключам (например, `ON p.category_id = c.id`). В результате СУБД SQLite вместо обычного внутреннего соединения выполнит **декартово произведение** (`CROSS JOIN`). Это приведет к тому, что каждая строка из таблицы `product` соединится с абсолютно каждой строкой из таблицы `categories`, сформировав избыточный и некорректный набор данных.

### Задача на предсказание результата
* **Тестовый запрос:** 
  ```sql
  SELECT p.title, c.name FROM product p LEFT JOIN categories c ON p.category_id = c.id;
  ```
* **Ответ:** Запрос выполнит левое внешнее соединение и вернет абсолютно **все записи из таблицы `product`**, независимо от того, привязана ли к ним категория. Для тех товаров, у которых поле `category_id` имеет значение `NULL` (или содержит идентификатор, отсутствующий в справочнике категорий), в результирующей колонке `c.name` будет автоматически выведено значение **`NULL`**.

### Продвинутый случай (Переписание RIGHT JOIN через LEFT JOIN)
* **Проблема:** СУБД SQLite исторически не поддерживает оператор `RIGHT JOIN`. Необходимо переписать логику правого соединения через левое.
* **Решение:** Для эмуляции `RIGHT JOIN` необходимо поменять таблицы местами в блоке `FROM / LEFT JOIN`. Ведущей таблицей (из которой выберутся все данные) станет `categories`.

**Итоговый корректный SQL-код:**
```sql
SELECT p.title, c.name AS category
FROM categories c
LEFT JOIN product p ON p.category_id = c.id;
```
