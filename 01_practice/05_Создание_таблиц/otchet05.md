## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Код с ошибкой:** 
  ```sql
  CREATE TABLE product (
      ...
      price REAL CHECK (price > 0),
      ...
  );
  
  INSERT INTO product (name, price) VALUES ('Тест', 0);
  ```
* **Вопрос:** Почему вставка не пройдёт?
* **Ответ:** Ограничение `CHECK (price > 0)` жестко требует, чтобы значение в столбце цены было строго больше нуля. Передаваемое значение `0` не удовлетворяет этому условию строгого неравенства, поэтому СУБД заблокирует операцию и выдаст ошибку нарушения бизнес-правила: `CHECK constraint failed`.

### Задача на предсказание результата
* **Сценарий:** Таблица `category` содержит запись `(id=1, name='Еда')`. Включен режим проверки внешних ключей: `PRAGMA foreign_keys = ON;`.
* **Выполняемые запросы:**
  ```sql
  INSERT INTO product (name, price, category_id) VALUES ('Хлеб', 40, 1);
  INSERT INTO product (name, price, category_id) VALUES ('Сыр', 200, 99);
  ```
* **Ответ:**
  * **Первая строка ('Хлеб')** успешно вставится в базу данных, так как указанный `category_id = 1` реально существует в связанной таблице `category`.
  * **Вторая строка ('Сыр')** завершится ошибкой `FOREIGN KEY constraint failed`. Поскольку в таблице `category` нет записи с `id = 99`, СУБД SQLite сработает корректно и защитит базу данных от появления «битой» ссылки на несуществующую категорию.
