# Отчет по практической работе №13: Индексы

## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Ситуация:** Студент вручную создал индекс на столбец `id`, который уже назначен в качестве первичного ключа (`PRIMARY KEY`).
* **Объяснение:** Действия студента ошибочны с точки зрения оптимизации, так как создание такого индекса является абсолютно избыточным. СУБД SQLite (как и любая другая реляционная СУБД) при назначении столбца первичным ключом (`PRIMARY KEY`) или навешивании ограничения `UNIQUE` автоматически генерирует под него уникальный системный индекс в фоновом режиме. Ручное дублирование этой структуры лишь зря тратит дисковую память и замедляет операции вставки/изменения записей.

### Задача на предсказание результата
* **Сценарий:** Создан индекс `CREATE INDEX idx ON product(price);`. Выполняется анализ запроса:
  ```sql
  EXPLAIN QUERY PLAN SELECT * FROM product WHERE price > 100;
  ```
* **Ответ:** План запроса наглядно покажет, что SQLite отказалась от полного сканирования таблицы (`SCAN`) в пользу быстрого бинарного поиска по созданному индексу. В выводе команды `EXPLAIN QUERY PLAN` отобразится строка:
  ```text
  SEARCH product USING INDEX idx (price > ?)
  ```
