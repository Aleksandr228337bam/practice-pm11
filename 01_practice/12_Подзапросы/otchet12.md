## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Запрос с ошибкой:** 
  ```sql
  SELECT * FROM product WHERE price > (SELECT price FROM product WHERE category_id = 1);
  ```
* **Объяснение ошибки:** Данный запрос вызовет критическую ошибку выполнения в том случае, если вложенный подзапрос вернет более одной строки (например, если в категории с `id = 1` находится несколько товаров с разными ценами). Математический оператор сравнения строго больше `>` является скалярным и принципиально не способен сравнить значение цены одной строки с целым списком/массивом возвращенных подзапросом значений. Для исправления ошибки оператор `>` необходимо заменить на `> ANY` / `> ALL` (в СУБД, поддерживающих это) или использовать агрегатную функцию в подзапросе: `(SELECT MAX(price) FROM ...)`.

### Задача на предсказание результата
* **Тестовый запрос:** 
  ```sql
  SELECT * FROM category c WHERE NOT EXISTS (SELECT 1 FROM product p WHERE p.category_id = c.id);
  ```
* **Исходные данные:** В базе данных заведены категории `1` и `2`, при этом имеющиеся товары привязаны только к категории `1`.
* **Ответ:** Запрос вернет ровно одну строку, содержащую **категорию 2**. Оператор `NOT EXISTS` пропускает во внешнюю выборку только те записи категорий, для которых внутренний коррелированный подзапрос возвращает пустой результат (то есть связанные товары полностью отсутствуют). Поскольку в категории 1 товары есть, она отсеивается, а пустая категория 2 выводится на экран.
