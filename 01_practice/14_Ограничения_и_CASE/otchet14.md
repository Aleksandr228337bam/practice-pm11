# Отчет по практической работе №14: Ограничения и оператор CASE

## 1. Цель работы
Изучить особенности декларативного контроля целостности данных в SQLite, освоить применение условного оператора `CASE` (простого и поискового типов) внутри SQL-запросов, а также рассмотреть функции фильтрации значений `COALESCE` и `NULLIF`.

В ходе практической работы была создана таблица с комплексными ограничениями `CHECK` и `UNIQUE`. Написаны условные запросы выборки и обновления данных. Скриншот выполнения работы из DB Browser прикреплен в текущей папке репозитория.

## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Запрос с ошибкой:** 
  ```sql
  SELECT name, CASE WHEN price > 100 THEN 'дорого' FROM product;
  ```
* **Объяснение ошибки:** Данный запрос вызовет синтаксическую ошибку (Syntax Error). В условной конструкции `CASE` пропущено обязательное завершающее ключевое слово `END`. Блок ветвления в языке SQL всегда должен иметь строгое явное окончание. 
* **Исправленный вариант запроса:**
  ```sql
  SELECT name, CASE WHEN price > 100 THEN 'дорого' END AS price_category FROM product;
  ```

### Задача на предсказание результата
* **Тестовый запрос:** 
  ```sql
  SELECT COALESCE(NULL, NULL, 5);
  ```
* **Ответ:** Запрос вернет целочисленное значение **5**.
* **Объяснение:** Встроенная функция `COALESCE` принимает на вход список аргументов, последовательно сканирует их слева направо и моментально возвращает первое встретившееся ей значение, которое не равно системному маркеру пустоты `NULL`. Так как первые два аргумента определены как `NULL`, функция пропускает их и успешно выводит число 5.
