# Отчет по практической работе №8: Ссылочная целостность

## 1. Цель работы
Изучить механизмы обеспечения ссылочной целостности данных в СУБД SQLite, освоить управление проверкой внешних ключей через системные команды `PRAGMA` и разобраться в каскадных операциях удаления данных.

## 2. Результаты выполнения заданий
В ходе практической работы были настроены связи между таблицами с использованием ограничений `FOREIGN KEY` и правил каскадного удаления `ON DELETE CASCADE`. Работа проверена в DB Browser. Скриншот, подтверждающий корректное создание и связывание таблиц, прикреплен в текущей папке репозитория.

## 3. Решение дополнительных задач модуля

### Задача на поиск ошибки
* **Сценарий:** Выполняется вставка записи с `client_id = 999` в дочернюю таблицу, при этом клиента с таким идентификатором нет в родительской таблице. Операция проходит успешно и не вызывает ошибку.
* **Объяснение:** Вставка проходит успешно, даже несмотря на то, что связанного клиента с `id = 999` не существует, потому что перед выполнением операции была запущена команда:
  ```sql
  PRAGMA foreign_keys = OFF;
  ```
  Данная директива полностью отключает в текущей сессии механизм принудительной проверки связей и ограничений внешних ключей в SQLite. В результате база данных пропускает некорректную запись, временно переводя контроль целостности в пассивный режим.

### Задача на предсказание результата
* **Сценарий:** Из родительской таблицы удаляется клиент со значением `id = 1`. Для связи между таблицами настроено ограничение каскадного удаления:
  ```sql
  ON DELETE CASCADE
  ```
* **Ответ:** При удалении клиента с `id = 1` СУБД автоматически отследит все зависимые записи в дочерней таблице `orders`. За счет включенного правила `ON DELETE CASCADE` все связанные с этим клиентом заказы (в данном случае заказ с `id = 1` и `client_id = 1`) будут автоматически и каскадно стерты из таблицы `orders`. Это гарантирует отсутствие "осиротевших" записей в базе данных.
